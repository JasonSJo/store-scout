# QUICKSTART — 후보지 확보부터 심의까지

> **사내 한정 · 대외 배포 금지.** 산출물은 내부 의사결정 자료입니다.
> 가맹희망자 제공용 예상매출액 산정서와 수치를 혼용하지 마십시오.

기호: 🙋 사람만 · 🤖 자동 · 💳 비용/쿼터 발생

> **후보지 데이터는 [`input/index.html`](input/index.html)(데이터 입력 페이지)에서 넣으십시오.**
> 실사 결과를 폼으로 채우면 파이프라인이 그대로 먹는 후보지 CSV 로 내보냅니다. 손으로 CSV 를
> 편집할 필요가 없고, 필수 항목·좌표 범위·이름 중복·치명 항목 미확인을 그 자리에서 잡아 줍니다.
> **주소를 검색하면 후보지명과 좌표가 함께 채워지고**, 네이버지도·네이버부동산·호갱노노·
> 일사편리로 바로 넘어가는 링크가 붙습니다(자세한 설정은 README 의 '데이터 입력 페이지').
> 공개 페이지이지만 **입력만** 다루므로 판정·매출 추정은 보여주지 않습니다.

---

## STEP 0 · 먼저 돌려 본다 (10분)

```bash
cd cafe-trade-area/analysis
pip install -r requirements.txt
./run_all.sh                    # 예시 데이터로 전 과정 (무료·네트워크 없음)
```

`output/심의표.md` 를 열어 어떤 판정이 어떤 근거로 나오는지 먼저 봅니다.
동봉 데이터는 전부 합성이며 실측이 아닙니다.

🙋 `설정.example.yaml` 을 `설정.yaml` 로 복사해 **우리 브랜드 값**으로 고칩니다 —
원재료율·로열티율·광고분담금율·고정인건비. 이 값이 BEP 와 margin 을 결정합니다.

## STEP 1 · 데이터 확보 (🙋 가장 오래 걸리는 단계)

| 데이터 | 어디서 | 주기 |
|---|---|---|
| 보행 네트워크(등시선) | OpenStreetMap → `fetch_isochrones.py --live` | 반기 |
| 100m 격자 인구 | 통계청 SGIS | 연 1회 |
| 유동인구 | 공공데이터포털 / 통신사 | 월 |
| 경쟁점 | 소상공인시장진흥공단 + 현장 실사 → `collect_competitors.py --live` | 분기 |
| 임대 시세 | 국토교통부 실거래가 + 중개업소 청취 | 건별 |

**🙋 반드시 사람이 해야 하는 것 — 07~09시 현장 통행량 실측 카운트.**
기지국 기반 유동인구는 도로 좌·우를 구분하지 못하는 경우가 많은데, `D_am` 과
방향성 보정은 알고리즘 정확도의 핵심 변수입니다. 이 절차 없이는 M2 이후 전 단계의
신뢰도가 확보되지 않습니다. 후보지마다 평일 오전 10분씩, 도로 양쪽을 따로 셉니다.

## STEP 2 · 등시선 (💳 API 쿼터)

```bash
export ORS_API_KEY="..."
python3 fetch_isochrones.py --live --out 등시선.geojson
```

🙋 **생성된 폴리곤을 GIS 에서 확인하십시오.** 라우팅 API 는 명세가 요구한 barrier
(횡단보도 없는 6차선 이상·하천·철로·옹벽·경사 10% 초과)를 자동으로 반영하지
않습니다. 커피는 유효 상권이 좁아, 반경 300m 안이어도 단절되면 수요가 0 에 수렴합니다.

> 등시선 없이도 돌아가지만(원형 폴백) 명세가 오차 흡수의 핵심이라고 지목한 단계를
> 통째로 건너뛰는 것이고, 산출물 전체에 경고가 붙습니다.

## STEP 3 · 경쟁점 (💳 API 쿼터)

```bash
export KAKAO_REST_KEY="..."
python3 collect_competitors.py --live --radius 700
```

🙋 수집 후 **티어를 현장 실사로 검증**하십시오 — 동일 가격대 / 저가형 / 스페셜티 /
비커피. 티어는 M3 흡인력의 브랜드가중을 좌우합니다.
🙋 **자사 기존점은 `자사=Y`** 로 표시해야 자기잠식이 계산됩니다.

## STEP 4 · 치명 항목 실사 (🙋 이 단계가 실질 방어선)

후보지 CSV 의 네 칸을 채웁니다. 하나라도 `Y` 면 점수·매출과 무관하게 **즉시 부결**입니다.

- [ ] `근저당_과다` — 등기부 확인. 선순위 권리로 보증금 회수가 불확실한가
- [ ] `임대인_불일치` — 등기부상 소유자와 계약 상대가 같은가. 전대차·자기거래 정황
- [ ] `소송_계류` — 명도 분쟁·소송이 걸려 있는가
- [ ] `인허가_불가` — 용도지역·정화조 용량으로 휴게음식점 인허가가 나는가

비워 두면 '통과' 판정에 **잠정** 표시가 붙습니다. 실사 전 통과는 통과가 아닙니다.

## STEP 5 · 심의 (🤖)

```bash
python3 review_sites.py --sites 후보지.csv --stores 기존점.csv \
    --cells 격자인구.csv --points 유동인구.csv \
    --competitors 경쟁점.csv --iso 등시선.geojson --settings 설정.yaml
```

→ `output/심의표.md` · `output/심의결과.json`

**읽는 순서**

1. **판정과 사유** — 부결 사유부터. 치명 플래그는 협상으로 뒤집히지 않습니다.
2. **margin 과 margin_low** — 하한 시나리오에서 적자면 총점과 무관하게 강등됩니다.
3. **데이터 경고** — 어떤 입력이 비어 있는지가 판정의 신뢰도를 정합니다.
4. **미검증 계수** — 리포트 말미 목록. 교정 전 산출물은 그만큼 불확실합니다.

```bash
python3 build_report.py --site "판교"     # 후보지별 심의 리포트
```

## STEP 6 · 협상 (🙋)

콘솔(`app/index.html`)에서 `output/심의결과.json` 을 불러오고 **손익 시뮬** 탭에서
임대료를 올려 봅니다. 어디서 보류가 부결로 바뀌는지가 협상의 한계선입니다.
M5 판정 산술만 다시 계산하므로 상권·수요·경쟁 값은 파이프라인 그대로입니다.

## STEP 5.5 · 지역 시세 대조 (💳 쿼터)

후보지에 법정동코드가 채워져 있으면 국토교통부 실거래가를 받아 지역 시세와 대조합니다.

```bash
DATA_GO_KR_KEY=... python3 collect_transactions.py --live --months 12
```

심의표에 `지역 실거래가 (참고)` 절이 붙습니다. **판정에는 들어가지 않습니다** —
제시된 보증금·권리금·임대료가 그 동네 수준을 벗어나는지 보는 용도입니다.

## STEP 6.5 · 수치 조정 (🙋)

알고리즘에 들어가는 수치는 코드나 CSV 를 고치지 말고 콘솔에서 직접 넣으십시오.
**후보지 한 곳의 실사 결과**(임대료·좌석수·치명 플래그 등)는 **후보지** 탭 하단
'입력값 수정' 에서, **모든 후보지에 공통인 계수**는 **계수 입력** 탭에서 넣습니다.

후보지 입력값 — 임대료를 올려 보거나, 실사에서 확인한 치명 플래그를 켜 보십시오.
치명 플래그는 하나만 해당해도 점수·매출과 무관하게 단독 부결이라 판정이 즉시 뒤집힙니다.
M1~M4 로 들어가는 값(좌표·좌석수·접근성·계약조건)은 **후보지 CSV 내보내기** 후:

```bash
cd analysis && python3 review_sites.py --sites ~/Downloads/sites.csv
```

계수 —

- **M5 임계값·잠식계수·운영 계수** — 넣는 즉시 판정이 다시 계산되고, 바뀐 후보지는
  `파이프라인 보류 → 통과` 처럼 원래 판정과 함께 표시됩니다.
  (후보지 입력값도 같은 방식으로 표시됩니다.)
- **M1~M4·M6 계수, 브랜드 티어 가중, Mode B 배점** — 브라우저가 다시 계산할 수 없습니다.
  **계수 파일 내보내기** → `coefficients.json` 을 `analysis/` 에 두고 파이프라인을
  다시 돌리면 전 모듈에 적용됩니다.

```bash
cd analysis && cp ~/Downloads/coefficients.json . && python3 review_sites.py
```

입력값이 적용된 심의표에는 **“콘솔에서 입력한 계수”** 절이 *명세값 → 입력값* 으로
그대로 실립니다. 임계값을 건드리는 것은 **심의 기준 자체를 바꾸는 행위**이므로,
근거와 적용 시점을 함께 남기십시오.

## STEP 7 · 개점 후 — M6 (🤖 + 🙋)

**이 단계를 건너뛰면 시스템을 운영하면 안 됩니다.** Mode B 는 M6 없이 순환논리를
벗어나지 못하고, 모든 계수가 미검증으로 남습니다.

```bash
python3 calibrate.py --actuals 실적.csv
```

수집할 것: 개점 후 6·12개월 실매출, 심의 당시 예측 중앙값, 인접 자사점 개점 전후 매출.

→ `output/보정_제안.md` — 사람이 검토해 `config.py`(또는 콘솔 **계수 입력** 탭)에
반영합니다. 계수를 바꾸면 과거 심의와 비교가 끊기므로
**변경 이력과 적용 시점을 남기십시오.**

- 정량 점수는 보조입니다. **실질 방어선은 부결 트리거**(치명 플래그·안전마진)입니다.

- 예측은 중앙값입니다. 가맹희망자 제공치가 이 값을 넘지 않도록 별도 통제하십시오.
