# 데이터 소스 — 무엇을 어디서 가져오고, 무엇은 못 가져오는가

알고리즘이 요구하는 입력 중 **사람이 만들어야 하는 것**과 **받아올 수 있는 것**을
가른 문서입니다. 받아올 수 있는 것은 어느 API 이고 얼마이며 갱신주기가 어떤지,
받아올 수 없는 것은 왜 없는지를 적습니다.

> ⚠ **이 문서의 API 명세는 실제 호출로 검증되지 않았습니다.** 개발 환경이 국내
> 공공데이터 호스트를 전부 차단하고 있어 한 번도 호출해 보지 못했습니다. 서비스명과
> 필드명은 공개 문서·검색으로 확인한 것과 관례를 따른 추정이 섞여 있습니다.
> 각 수집기는 응답을 못 읽으면 **응답 앞부분을 그대로 출력**하므로, 첫 실호출 한 번이면
> 실제 스키마를 알 수 있고 고칠 자리는 `ENDPOINT`/`FIELDS` 두 곳뿐입니다.

## 1. 유동인구 — 실측을 대신할 방법은 없다

### 알고리즘이 요구하는 것

M2 는 **07~09시 통행량을 P5 폴리곤 안에서, 도로 좌·우로 나눠** 셉니다.

```
D_am_adj = D_am_같은편 + (D_am_반대편 × 횡단저항 0.3)
```

지점 단위·시간대 단위·도로변 단위 — 세 조건을 모두 만족하는 공개 데이터는 없습니다.
명세가 "현장 실측 카운트"를 요구하는 이유입니다.

### 그래서 무엇을 쓰는가 — 영역 안분

`collect_foot_traffic.py` 가 **서울시 상권분석서비스 길단위인구(상권 단위)** 를 받아
상권 전체 값을 P5 면적비로 안분합니다.

```
지점_인원 = 영역_인원 × (P5면적 ÷ 상권면적) × 유동_안분_집중계수
```

- 서비스: `TbgisTrdarRelm`(상권영역 — 면적·좌표), 길단위인구(서비스명 미검증)
- 호출: `http://openapi.seoul.go.kr:8088/{KEY}/json/{서비스명}/{시작}/{끝}/`
- 키: 서울 열린데이터광장 무료 발급 → `SEOUL_OPENAPI_KEY`

### 오차가 세 겹이고, 전부 같은 방향이다

| # | 오차 | 방향 |
|---|---|---|
| 1 | 영역 → 지점 안분이 균등분포를 가정 (실제는 간선도로변 집중) | 과대 |
| 2 | 공개 데이터 구간이 06~11시 (명세는 07~09시) | 과대 |
| 3 | 도로 좌·우 구분 없음 → 전부 '같은 편' 계산 | 과대 |

**셋 다 D_am 을 부풀립니다.** 이 값으로 나온 통과는 낙관 쪽으로 치우쳐 있습니다.
M2 는 안분이 한 건이라도 일어나면 경고를 남기고, 그 경고는 실측으로 바뀌기 전까지
사라지지 않습니다.

`단위면적_m2` 가 없는 영역 행은 **버립니다** — 추측한 면적으로 나눈 값은 근거가 아닙니다.

### 서울 밖

상권분석서비스는 서울 전용입니다. 전국은 소상공인시장진흥공단 상권정보(추정 유동인구)
또는 통신사 데이터가 후보입니다. 통신사 쪽은 `collect_carrier_flow.py` 로 붙였고,
받는 방법이 셋으로 갈립니다.

**전국을 시간대별로 덮는 무료 공개 API 는 없습니다.** 확인한 사실이 이렇습니다.

| 공급자 | 통신사 | 받는 법 | 비용 | 범위 |
|---|---|---|---|---|
| KT PLIP | KT | **반입(CSV)** | 기업 계약 | 전국 |
| SKT 지오비전 | SKT | **반입(CSV)** | 기업 계약 | 전국 250개 시군구 |
| LG U+ 유동인구 | LG U+ | **반입(CSV)** | 기업 계약 | 전국 (50×50m 블록) |
| 서울 생활인구 | KT (LTE 시그널) | 공개 API | 무료 | **서울시만** |
| SKT 지오비전 퍼즐 | SKT | API (앱키·승인) | 무료 범위 있음 | 상품마다 다름 |
| 공공데이터포털·빅데이터 플랫폼 | 지자체별 | 반입 | 무료(가입) | 지자체별 |

전국을 덮으려면 **통신사 계약이 현실적**입니다. 계약형은 공개 API 가 없어 받은
파일을 `--import` 로 넣고, 지역별로 나눠 받았으면 여러 개를 한 번에 넣어 합칩니다
(같은 구역이 겹쳐 오면 한 번만 넣습니다 — 그대로 더하면 D_am 이 배로 뜁니다).

무료로 열린 것은 지역 단위로 파편화돼 있고 갱신이 끊긴 자료가 많습니다.

두 가지를 먼저 알고 쓰십시오.

- **자료 공백이 시장 평가로 읽힙니다 — 전국으로 갈 때 가장 큰 위험입니다.**
  유동인구가 없는 후보지는 D_am 이 0 이 되고, S 는 풀 안 min-max 정규화라 바닥에
  깔립니다(13개 지표 중 '오전유동'·'임대료대비객수효율' 둘이 D_am 에서 나옵니다).
  상권이 나빠서가 아니라 자료를 못 받아서 낮아지는 건데 심의표로는 구분되지
  않습니다. **심의 전에 `--coverage` 를 돌리십시오** — 후보지별로 데이터 유무를
  말해 주고, `--strict` 면 빠진 곳이 있을 때 0 이 아닌 코드로 끝납니다.
- **실측이 아닙니다.** 기지국 신호는 '그 구역에 있었다' 이지 '그 앞을 걸어갔다' 가
  아닙니다. 도로 좌·우 구분이 없어 M2 가 횡단저항을 적용하지 못하고, 산출물에
  그 사실이 경고로 남습니다.
- **구역 면적표가 함께 필요합니다.** M2 는 영역 값을 P5 면적비로 안분하므로
  구역코드→면적(m²) 표가 없으면 행을 만들지 않습니다(추측한 면적으로 나눈 값은
  근거가 아닙니다). 통계청 SGIS 집계구 경계에서 만듭니다.
- **집계구를 쓰십시오.** 행정동은 1~3km² 인데 P5(도보 5분)는 0.35km² 안팎이라,
  중심점이 P5 안에 드는 행정동이 거의 없습니다.

### 실측으로 가는 길

`실적.csv` 에 이미 `실측_같은편_오전`·`실측_반대편_오전` 열이 있고 M6 가 읽습니다.
현장 카운트를 몇 건이라도 넣으면 M6 가 `유동_안분_집중계수`를 교정할 수 있습니다 —
대용값을 실측에 맞춰 당기는 경로가 이미 뚫려 있습니다.

## 2. 부동산 정보 — 여기가 제일 막혀 있다

치명 플래그 4종은 단독으로 부결시키는 항목이라, 자동화 가능성을 하나씩 따졌습니다.

### 등기부(근저당 과다 · 임대인 불일치) — 공식 API 없음

- **인터넷등기소는 등기부등본 열람 API 를 제공하지 않습니다.** 등기정보광장
  (`data.iros.go.kr`)의 Open API 는 **통계**(등기 현황 집계)만 줍니다. 개별 부동산의
  갑구·을구를 주지 않으므로 근저당액도 소유자도 알 수 없습니다.
- 시중의 "등기부등본 API" 는 전부 **제3자 스크래핑 대행**입니다(CODEF, Tilko, Hyphen 등).
  건당 과금이고, 열람 수수료(700원)가 별도로 붙습니다.
- **임대인 불일치**는 등기부 갑구의 소유자와 계약 상대를 대조해야만 나옵니다.
  등기부 없이는 판정할 방법이 없습니다.

**권고**: 자동화하지 마십시오. 최종 후보 2~3곳으로 좁힌 뒤 사람이 열람하는 편이
비용·리스크 모두 낮습니다. 전 후보지에 스크래핑 대행을 돌리는 것은 건당 비용도 비용이지만,
약관·개인정보 측면에서 회사가 질 위험이 큽니다.

### 소송 계류 — 조회 자체가 불가능

대법원 **나의사건검색은 사건번호를 알아야** 조회됩니다. 부동산 주소로 역검색하는
공개 경로가 없습니다.

**대안**: 등기부를 열람하면 **가압류·가처분·경매개시결정**이 을구/갑구에 나타납니다.
분쟁의 상당수는 여기서 잡힙니다. 즉 소송 확인도 결국 등기부로 수렴합니다.

### 인허가 — 여기는 무료로 자동화 가능

세 갈래가 모두 공개 API 입니다.

1. **음식점 인허가 이력** — 구 LOCALDATA. **2026-04-16 서비스 종료**되어 공공데이터포털
   (`data.go.kr`)로 이관됐습니다. 같은 주소·건물의 과거 휴게음식점 인허가 이력이 있으면
   인허가 가능성이 높다는 **강한 힌트**입니다.
   덤으로 **폐업 이력 → 상권 회전율** 이라는 별개의 지표가 나옵니다.
2. **건축물대장** (국토부) — 주용도, **위반건축물 여부**. 위반건축물이면 영업신고가
   반려될 수 있습니다.
3. **토지이용계획** (국토부) — 용도지역. 명세의 `인허가_불가` 사유 중 '용도지역' 이
   여기서 직접 확인됩니다.

**단, 이것으로 플래그를 자동으로 채우면 안 됩니다.** 정화조 용량은 어느 API 에도 없고,
지자체 재량도 큽니다. 위 셋은 "실사 우선순위를 매기는 힌트"이지 "실사 완료"가 아닙니다.
`quick_site.py` 가 치명 플래그를 `N` 으로 채우지 않는 것과 같은 이유입니다.

**미연동**입니다 — 다음 작업 후보로 남깁니다.

## 3. 기존점 실매출 — 연 1회 갱신 구조

### 사내 실매출 (Mode A·B 의 본체)

`기존점.csv` 의 `월매출_만원` 이 M4 의 전부입니다.
- **Mode A(회귀)**: 유효표본 15개 이상이면 로그선형 회귀. 점포별 좌석수·층·전면폭·
  상권 지표가 함께 있어야 설명변수가 만들어집니다.
- **Mode B(앵커링)**: `기준점포=Y` 인 점포의 실매출을 S 비율로 조정. **좌표가 필수**입니다
  (S 를 같은 척도에 놓아야 하므로).

타지점 매출을 매년 갱신하실 계획이면, 갱신해야 하는 것은 `월매출_만원` 하나가 아니라
**그 점포의 속성 한 벌 전체**입니다. 매출만 새로 넣고 좌석수·임대료가 몇 년 전 값이면
회귀 계수가 조용히 틀어집니다.

### 타브랜드 매출 (이번에 추가한 대조선)

`collect_benchmarks.py` — **공정거래위원회 가맹사업 정보공개서** 공시 자료.

- 서비스: `공정거래위원회_가맹정보_브랜드별 가맹점 현황` (data.go.kr, 무료)
- 키: `DATA_GO_KR_KEY` — **실거래가와 같은 키**를 씁니다
- 필드: 가맹사업기준년도 · 브랜드명 · 시도 · 가맹점수 · **평균매출금액** ·
  **면적당 평균매출금액**
- **금액 단위는 천원**입니다. 만원으로 환산하지 않으면 벤치마크가 10배 어긋납니다.
- 기본 조회 연도는 **작년**입니다 — 공시는 전년도 실적이 최신이라 올해를 물으면 빈 결과가 옵니다.

**갱신주기가 연 1회인 것은 우리 사정이 아니라 데이터의 성질입니다.** 정보공개서 등록
주기가 연 단위라 더 자주 받아도 같은 값이 옵니다. 말씀하신 "전년도 데이터로 매년 갱신"이
이 데이터의 구조와 정확히 맞습니다.

### 대체가 아니라 대조선인 이유

공시 데이터는 **브랜드 × 시도 단위 평균 한 숫자**입니다. 점포별 좌석수도, 좌표도
없습니다. 그래서 회귀 표본으로도 앵커로도 **직접 쓸 수 없습니다.**

쓸 수 있는 자리는 하나입니다:

```
업계 기대 월매출 ≈ 면적당_연매출_중앙(만원/㎡) × 전용면적_평 × 3.305785 ÷ 12
```

M4 추정치를 이 값과 나란히 놓아, 추정이 업계에서 얼마나 떨어져 있는지 봅니다.
사내 실적이 쌓이기 전까지 추정치를 검증할 **유일한 외부 기준**입니다.
평균이 아니라 중앙값을 씁니다 — 브랜드 몇 개가 표본을 통째로 끌어올립니다.

> 현재 수집·산출까지만 되어 있고 **심의표 판정에는 연결하지 않았습니다.** 실거래가 때처럼
> 대조 신호로 넣을 수 있지만, 표본이 브랜드×시도 단위라 후보지 한 곳에 적용할 때의
> 오차가 실거래가보다 큽니다. 실제 데이터를 한 번 받아 본 뒤 판단하는 편이 맞습니다.

## 4. 격자 인구 H·W — 통계청 SGIS (전국)

M2 의 배후 수요(`H` 세대수, `W` 직장인구)는 `collect_grid_population.py` 가
통계청 **SGIS**(`sgisapi.kostat.go.kr`, 무료 키)에서 받습니다. **전국 어디든 같은
방식으로 나옵니다** — 지역별로 소스가 갈리는 유동인구와 다릅니다.

```bash
SGIS_KEY=... SGIS_SECRET=... python3 collect_grid_population.py --live --sites 후보지.csv
```

유동인구와 달리 **추정이 아닙니다.** 거주·사업체는 등록 데이터라 기지국 신호처럼
'있었을 것' 을 세는 값이 아니고, 그래서 M2 도 이 값에는 대용 경고를 붙이지 않습니다.

후보지마다 반경 800m(P10 도보 10분 667m 를 덮음)를 조회하고, 후보지들의 조회 영역이
겹쳐 같은 격자가 여러 번 와도 한 번만 넣습니다 — 그대로 더하면 H·W 가 부풀어
그 후보지의 배후 수요가 근거 없이 커집니다.

**확인한 것과 아직 못 한 것**

- ✅ 인증: `consumer_key`/`consumer_secret` → `result.accessToken` (문서 확인)
- ❓ 조회: SGIS 통계 API 는 좌표 사각형이 아니라 **`adm_cd`(행정구역코드) + `year`**
  로 부르는 형태입니다(`household.json` → `household_cnt`, `company.json` → 종사자수).
  격자 단위 상품이 따로 있는지는 확인하지 못했습니다.

키를 발급받으신 뒤 이 한 줄을 돌려 주십시오 — 후보 엔드포인트를 하나씩 눌러 보고
무엇이 답하는지, 응답 필드가 무엇인지 그대로 출력합니다.

```bash
SGIS_KEY=... SGIS_SECRET=... python3 collect_grid_population.py --probe
```

그 출력이 연동을 확정하는 근거입니다. 추측으로 코드를 더 쌓지 않고 거기서 맞춥니다.

### KOSIS (국가통계포털) — 같은 자리를 채우는 두 번째 길

전국·무료이고 주민등록인구와 전국사업체조사(종사자수)가 있습니다. 어려운 것은
호출이 아니라 **어느 통계표(`tblId`)를 쓸지 고르는 것**입니다 — 표가 수만 개이고
이름이 비슷해서, 코드에 박아 두면 그게 맞는 표인지 아무도 확인하지 못합니다.

```bash
KOSIS_API_KEY=... python3 collect_grid_population.py --find 가구 --find 종사자
```

통계표 트리를 내려가며 이름에 그 낱말이 든 표를 찾아 `ORG_ID`·`TBL_ID`·경로를
보여 줍니다. **분류 코드를 외워 박지 않기 위한 것입니다** — 실제로 확인해 보니
`A_1` 은 '인구·가구' 가 아니라 '인구이동' 이었습니다. 그런 추측은 틀려도 조용히
빈 결과만 돌아와서 맞는지 알 수가 없습니다.

```
찾은 통계표 2개:
  ORG_ID=101 TBL_ID=DT_1JC1501
    행정구역별 가구원수별 가구(일반가구)
    경로: 인구 > 인구총조사
  ORG_ID=101 TBL_ID=DT_1K52C01
    행정구역별 사업체수 및 종사자수
    경로: 사업·기업 > 전국사업체조사
```

`--probe` 는 지정한 분류의 목록을 그대로 보여 줍니다. 표를 고른 뒤에는 **코드를 고칠 필요 없이
플래그로** 돌립니다:

```bash
KOSIS_API_KEY=... python3 collect_grid_population.py --source kosis --live \
    --areas 행정구역.csv \
    --tbl-id-household DT_xxxx --tbl-id-worker DT_yyyy
```

`--areas` 표의 뼈대는 도구가 만들어 줍니다 — 전국 229개를 다 채울 필요 없이,
이번 후보지가 속한 시군구만 채우면 됩니다.

```bash
python3 collect_grid_population.py --make-areas --sites 후보지.csv --areas 행정구역.csv
```

```
--areas 뼈대를 만들었습니다 — 시군구 3개 → 행정구역.csv
  11200  ← 성수 연무장길
  11680  ← 강남역 11번출구
  41135  ← 판교 유스페이스
```

면적과 좌표는 **비워서** 냅니다(지어내면 그 값으로 배후 수요가 안분되고 아무도
추측이었다는 걸 모르게 됩니다). 면적은 KOSIS '지적통계', 중심점은 행정안전부
행정구역 경계의 도형 중심에서 채웁니다.

`--areas` 는 구역코드 → 면적(m²)·중심점 표입니다. KOSIS 는 행정구역 코드와 값만 주고
좌표도 면적도 주지 않는데, M2 는 둘 다 필요합니다(중심점으로 P10 과 겹치는지 보고,
면적으로 안분). 없으면 행을 만들지 않습니다 — 추측해 나눈 값은 근거가 아닙니다.
유동인구 쪽 `--areas` 와 같은 형식이라 표 하나를 양쪽에 씁니다.

(키 발급: <https://kosis.kr/openapi/index/index.jsp> · 활용용도 웹개발 · 자동승인)

### ⚠ 무료 전국 자료는 대부분 행정구역 단위입니다

SGIS 통계 API 도 KOSIS 도 격자가 아니라 행정동/시군구 단위로 줍니다. 그걸
`격자인구.csv` 에 넣으면 M2 가 P10 과 겹친 면적비로 안분하는데, 여기에는
**균등분포 가정**이 들어갑니다 — 행정동은 1~3km² 이고 P10 은 0.35km² 안팎이라
그 안에서 사람이 어디 몰려 있는지는 통째로 사라집니다.

유동인구 쪽은 같은 안분을 할 때 크게 경고하면서 배후 인구 쪽은 조용했습니다.
이제 한 변 300m 를 넘는 칸이 쓰이면 M2 가 같은 기준으로 경고합니다. 100m 격자
자료로 바꾸면 사라지는 오차입니다.

## 남은 진실

세 가지를 다 붙여도 **알고리즘이 요구하는 정확도에는 못 미칩니다.**

- 유동인구는 대용이고, 오차가 전부 낙관 방향입니다.
- 등기·소송은 사람이 열람하는 것 말고 방법이 없습니다.
- 기존점 실매출은 외부에 없습니다 — 회사가 쌓아야 하는 자산입니다.

이 문서의 목적은 그 격차를 없애는 게 아니라 **어디가 비어 있는지 매번 같은 자리에서
보이게** 하는 것입니다. 비어 있다는 사실이 산출물에서 사라지는 순간, 심의는
근거 없이 통과를 내기 시작합니다.
