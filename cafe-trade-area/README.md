# 커피 프랜차이즈 상권분석 시스템 — 점포개발 심의용

> **사내 한정 · 대외 배포 금지**
>
> 본 시스템의 산출물은 내부 의사결정 자료입니다. 가맹희망자에게 제공하는
> **예상매출액 산정서와 수치를 혼용하지 마십시오.** 제공치가 내부 중앙값 추정치를
> 초과하지 않도록 별도 통제해야 합니다.

「커피 프랜차이즈 상권분석 알고리즘 v1.0」 명세를 구현한 파이프라인과 사내 콘솔입니다.

```
M1 상권 획정 → M2 수요 변수 → M3 경쟁 배분 → M4 매출 추정
                                              ↓
                                     M5 판정 로직 → M6 사후 보정
```

## 설계 원칙

| 원칙 | 구현 |
|---|---|
| 추정 편향 | 중앙값 기준. 예측구간(25/50/75) 전체를 심의 재료로 낸다 |
| 판정 구조 | 정량 점수는 보조 — **부결 트리거가 실질 방어선** |
| 출력 형태 | 종합점수 S + 3단 판정(통과/보류/부결) |
| 필수 조건 | **M6 사후 보정 루프 없이는 운영 금지** |

## 모듈

### M1 · 상권 획정 (Isochrone)

OSM 보행 네트워크(4km/h) 기준 등시선 `P5`·`P10` 을 쓰고 잔존율을 냅니다.

```
R = area(P10) ÷ (π × 667m²)        667m = 4km/h × 10분
```

**등시선은 파이프라인이 만들지 않습니다.** barrier 처리(횡단보도 없는 6차선 이상·
하천·철로·옹벽·경사 10% 초과)가 필요한 작업이라 밖에서 만들어 GeoJSON 으로 넣습니다.
경로는 셋입니다 — ① 사전 생성 파일 ② `fetch_isochrones.py --live` ③ 원형 폴백.
③은 명세가 "오차의 가장 큰 부분을 흡수한다"고 지목한 단계를 건너뛰는 것이므로
산출물 전체에 경고가 따라붙습니다.

### M2 · 수요 변수

100m 격자를 등시선과 면적 가중 교차합니다. 유동인구는 도로 좌·우로 나눠 보정합니다.

```
H = Σ(격자세대수 × 격자∩P10 면적비)      W = Σ(격자직장인구 × …)
D_am_adj = D_am_같은편 + (D_am_반대편 × 0.3)
```

### M3 · 경쟁 배분 (Huff)

```
S_i = (A_i / d_i^λ) ÷ Σ_j (A_j / d_j^λ)      A = 좌석수^0.5 × 브랜드가중,  λ = 2.2
```

명세의 식은 수요 원점 하나에 대한 정의입니다. 실제로는 수요가 상권에 흩어져
있으므로 M2 의 격자를 원점으로 삼아 칸마다 점유율을 구하고 수요로 가중평균합니다.
비교용으로 수요중심 한 점 값(`S_점`)도 함께 내지만, 그 원점은 후보지와 거의 겹쳐
발산하므로 **판정에는 쓰지 않습니다.**

### M4 · 매출 추정 (2모드)

- **Mode A** (유효표본 ≥ 15) 로그선형 OLS. 출력은 점추정이 아니라 **예측구간**입니다.
  하한/중앙/상한은 out-of-fold 잔차의 25/50/75 분위로 만듭니다 — 정규성 가정 없이
  실제로 빗나간 만큼만 벌립니다. 표본 < 40 이면 LOOCV, 이상이면 5-fold.
- **Mode B** (< 15) 기준점포 실매출 × (S ÷ S_기준점포).

### M5 · 판정

```
BEP = F ÷ (1 - v)      margin = (R_median - BEP) ÷ R_median
overlap = area(P10_후보 ∩ P10_기존점) ÷ area(P10_후보)
잠식액 = overlap × 기존점_월매출 × κ

IF   치명플래그 ≥ 1  OR  margin < 0.15                            → 부결
ELIF margin < 0.30 OR S < 70 OR overlap > 0.30 OR margin_low < 0  → 보류
ELSE                                                              → 통과
```

치명 플래그(근저당·임대인 불일치·소송·인허가)는 점수·매출과 무관하게 **단독으로**
부결시킵니다. 실사 전이라 칸이 비어 있으면 '통과'도 잠정으로 표시합니다.

### M6 · 사후 보정

개점 후 6·12개월 실매출로 MAPE 를 기록하고(20% 초과 3연속 → 재적합), λ·κ·모드 전환을
검토합니다. **계수를 자동으로 바꾸지 않습니다** — 제안서를 내고 사람이 반영합니다.
심의 기준이 아무도 모르게 바뀌는 쪽이 더 위험합니다.

## 실행

```bash
cd cafe-trade-area/analysis
pip install -r requirements.txt        # PyYAML 하나

./run_all.sh                           # 예시 데이터로 전 과정 (무료·네트워크 없음)
./run_all.sh --live                    # 등시선·경쟁점 실제 수집까지
./run_all.sh --stores 기존점.example_초기.csv   # Mode B 경로 확인
```

산출물은 `analysis/output/` 에 쌓입니다 — 심의표·후보지별 리포트·보정 제안.
콘솔에서 보려면 `app/index.html` 을 열고 `output/심의결과.json` 을 불러오면 됩니다.

후보지 한 곳의 실사값(임대료·좌석수·치명 플래그 등)은 콘솔 **후보지** 탭 하단
'입력값 수정' 에서 고치고, 필요하면 **후보지 CSV 내보내기** 후
`python3 review_sites.py --sites sites.csv` 로 다시 돌립니다.

모든 후보지에 공통인 계수를 바꿔 보려면 콘솔 **계수 입력** 탭을 쓰십시오. M5 임계값·
잠식계수·운영 계수는 즉시 다시 계산되고, M1~M4·M6 계수와 배점은
`coefficients.json` 으로 내보내 파이프라인에 넣습니다:

```bash
cd analysis && cp ~/Downloads/coefficients.json . && python3 review_sites.py
```

입력값이 적용되면 심의표에 **“콘솔에서 입력한 계수”** 절이 *명세값 → 입력값* 으로
실려, 어떤 숫자가 명세가 아니라 사람이 넣은 값인지가 남습니다.

| 파일 | 내용 | 출처 |
|---|---|---|
| `후보지.csv` | 좌표·면적·임대조건·치명 플래그 실사 결과 | 중개업소 · 등기부 · 현장 |
| `기존점.csv` | 자사 점포 실매출 + 같은 속성 | 사내 |
| `격자인구.csv` | 100m 격자 세대수·직장인구 | 통계청 SGIS (연 1회) |
| `유동인구.csv` | 시간대·도로변별 통행량 | 공공데이터포털/통신사 (월) · **07~09시 현장 실측 필수** |
| `경쟁점.csv` | 좌표·브랜드·티어·좌석수 | 소상공인시장진흥공단 + 현장 실사 (분기) |
| `등시선.geojson` | P5·P10 폴리곤 | OSM 보행 네트워크 (반기) |
| `실적.csv` | 개점 후 6·12개월 실매출 | 사내 — M6 입력 |

동봉한 `*.example.*` 는 **전부 합성 데이터**입니다. `make_fixtures.py` 가 만들며,
기존점 실매출은 참 모델에 로그정규 잡음을 얹어 생성했습니다. 실측이 아닙니다.

## 알려진 한계 (심의 시 반드시 고지)

1. **Mode B 는 순환논리에 가깝습니다.** 임의 배점 S 로 매출을 추정하고 그 추정치로
   판단합니다. 검증되는 것은 사후 실적뿐이므로, Mode B 단계에서는 알고리즘 결과를
   참고자료로만 쓰고 최종 판단은 부결 트리거에 둡니다.
2. **유동인구 해상도.** 기지국 기반 추정은 시간대 정밀도가 낮고 도로 좌·우 구분이
   안 되는 경우가 많습니다. `D_am` 은 정확도의 핵심 변수이므로 **07~09시 현장 통행량
   실측 카운트가 필수 절차**입니다.
3. **계수 전반이 미검증입니다.** λ=2.2 · 횡단저항 0.3 · κ=0.5 · 브랜드 티어 가중 ·
   축별 배점 — 전부 실무 판단 초기값입니다. `config.py` 가 검증 상태를 함께 들고
   있고, 모든 리포트 말미에 미검증 계수 목록이 인쇄됩니다. 콘솔 **계수 입력** 탭에서
   값을 바꿔 결과가 얼마나 움직이는지 직접 확인할 수 있고, 바꾼 값은 산출물에
   기록으로 남습니다 — 다만 **바꾼다고 검증되는 것은 아닙니다.** 검증은 M6 뿐입니다.
4. **`S < 70` 임계가 현재 풀에서 축퇴합니다.** (임계값은 콘솔 계수 입력 또는
   `coefficients.json` 으로 조정할 수 있습니다.) S 는 풀 내 min-max 정규화라 모든
   지표에서 동시에 1등이어야 100 에 닿습니다. 예시 데이터에서 풀 최댓값은 63 이고,
   그 결과 'S < 70' 이 모든 후보지에 무조건 걸려 변별력이 없습니다. 코드가 이 상황을
   감지해 심의표에 경고를 찍습니다 — 임계값을 포트폴리오 기준으로 재설정할지,
   정규화 방식을 바꿀지는 결정이 필요한 사항입니다.

## 데이터 입력 페이지 (`input/`)

후보지 실사 결과를 폼으로 받아 파이프라인 입력 CSV(`sites.csv`)로 내보냅니다.
**좌표·후보지명을 손으로 적지 않습니다** — 주소를 검색하면 함께 채워집니다.
좌표는 오타 한 자리에 상권이 통째로 어긋나는 값이라 직접 입력을 열어 두지 않았습니다.

### 주소 검색 — 두 경로

| | 필요한 것 | 되는 것 |
|---|---|---|
| **카카오맵 JS SDK** | 카카오 개발자센터 JS 키 | 주소·상호 검색 → **주소 + 좌표** 자동 |
| **다음 우편번호** (기본) | 없음 | 주소만. 좌표는 지도에서 복사해 붙여넣기 |

JS 키는 **도메인 제한**으로 보호되므로 공개 페이지에 넣어도 안전합니다(서버 키와 다릅니다).
페이지의 **키 넣기**에 입력하면 그 브라우저에만 저장됩니다. 배포본에서 쓰려면 카카오
개발자센터에서 사이트 도메인(`https://jasonsjo.github.io`)을 등록해야 합니다.

좌표 붙여넣기는 `37.5445, 127.0557` 형태를 받고, 경도가 먼저 와도 한국 범위로 판별해
바로잡습니다. 범위 밖 값은 거절합니다 — 조용히 통과시키면 상권이 다른 곳에 잡힙니다.

### 우편번호 · 법정동코드

주소를 고르면 **우편번호(5자리)** 와 **법정동코드(10자리)** 도 함께 받아 CSV 에 싣습니다.
(우편번호 서비스는 둘 다 주고, 카카오 주소 검색도 둘 다 줍니다. 카카오 *장소* 검색은
주지 않으므로 그때는 빈 값으로 둡니다 — 이미 있는 값을 빈 값으로 덮지 않습니다.)

두 값은 **M1~M6 계산에 들어가지 않습니다.** 상권·수요·경쟁은 전부 좌표로 잡습니다.
`analysis/tests/test_address_codes.py` 가 계산 모듈이 이 열을 읽지 않는다는 사실을
고정해 둡니다 — 쓰기 시작하면 테스트가 먼저 알려 줍니다. 대신 두 값은 심의표와
`심의결과.json` 에 그대로 실려 서류·조회에 쓰입니다.

법정동코드가 쓸모 있는 이유는 **앞 5자리가 국토교통부 실거래가 API 의 지역코드
(`LAWD_CD`)** 이기 때문입니다. 화면에도 잘라서 함께 보여 줍니다
(`1120012400` → `11200`). 이 값으로 `collect_transactions.py` 가 실거래가를 받아옵니다.

### 부동산 정보 — 링크만

네이버지도 · 네이버 부동산 · 호갱노노 · 일사편리(국토교통부)를 주소로 **새 탭에 엽니다.**
데이터를 가져오지는 **않습니다** — 공개 API 가 없고, 약관이 스크래핑을 금지하며,
정적 페이지는 CORS 로 막힙니다. 주소를 네 곳에 복붙하는 수고만 없앱니다.

> 각 서비스의 검색 URL 형식은 언제든 바뀔 수 있습니다. 어긋나도 해당 사이트에는
> 도착하므로 거기서 검색하면 됩니다. 형식이 바뀐 것을 발견하면
> `input/js/place.js` 의 `SERVICES` 를 고치십시오.

```bash
                        --settings output/consult/설정.yaml
```

### 상담에서 받는 값이 어디로 가는가

| 항목 | 목적지 |
|---|---|
| 고객명 · 연락처 · 거주지 · 근무지 | **개인정보** — 상담 기록 전용. 알고리즘·심의표 어디에도 안 들어감 |
| 창업 희망 지역 1·2·3 | 필터 |
| 희망 평수 | 필터 (±30%) |
| 희망 상권 (오피스·주거·학교·병원·메인·복합) | 필터 |
| 보증금 · 권리금 | 필터 (투자 한도) — 알고리즘 미사용 |
| **투자금 형태** (현금 / 현금+대출 / 현금+대출+리스) | **알고리즘** — 월 금융비용 → 고정비 |
| **운영 형태** (오토 / 점주+알바 / 점주) | **알고리즘** — 고정인건비 |

**판정에 실제로 닿는 것은 뒤의 둘뿐입니다.** 둘 다 고정비 F 를 바꾸고,
F 가 바뀌면 BEP → margin → 판정이 바뀝니다. 예시 후보지에서 운영 형태만
`점주+알바` → `점주` 로 바꾸면 BEP 2,430 → 1,865만원, margin 53.0% → 64.0% 로 움직입니다.

금액은 `설정.yaml` 의 `운영형태`·`투자금형태` 블록에 있습니다 — **회사 실정에 맞게
고치십시오.** 기본값은 통상 영업(12시간) 기준의 자리표시자입니다.

### 개인정보

상담 페이지는 이 저장소에서 **개인정보를 다루는 유일한 화면**입니다.

- **서버가 없습니다.** 입력값은 브라우저 `localStorage` 에만 남고 어디로도 전송되지
  않습니다. 배포 단계에서 `fetch`·`XMLHttpRequest`·`sendBeacon`·`WebSocket` 이
  섞이면 **배포를 중단**합니다.
- **수집·이용 동의 전에는 고객 정보를 입력·저장할 수 없습니다.** 동의를 해제하면
  이미 넣은 고객 정보도 지웁니다.
- 내보내는 파일이 둘로 나뉩니다 — `consult-card.md`(개인정보 포함, 상담사 보관)와
  `consult.json`(개인정보 제외, 파이프라인 입력). `consult.py` 는 개인정보 키를
  **아예 읽지 않습니다.** 심의 자료는 사내 회람 문서라 고객 연락처가 들어갈 자리가 아닙니다.
- 상담이 끝나면 **전체 비우기**로 지우십시오.

### 필터는 알고리즘이 아닙니다

조건에 맞지 않는 후보지는 **점수가 깎이는 게 아니라 목록에서 빠집니다.**
그래서 무엇이 왜 빠졌는지 `상담반영.md` 에 남깁니다. 조건이 지나치게 좁아
남은 후보지가 없으면 그렇게 말합니다 — 조건에 맞춘다고 판정 기준을 낮추지 않습니다.

## 데이터 소스

어떤 입력을 어디서 받아오고 무엇은 못 받아오는지는 **[docs/데이터소스.md](docs/데이터소스.md)**
에 한 장으로 정리했습니다 — API·비용·갱신주기, 그리고 등기·소송처럼 자동화가 불가능한
항목이 왜 불가능한지까지.

요약하면 세 가지가 여전히 비어 있습니다.

- **유동인구** — 서울 상권분석서비스로 **대용**은 됩니다(`collect_foot_traffic.py`).
  영역 값을 P5 면적비로 안분하며, 오차가 세 겹이고 **전부 D_am 을 과대평가하는 방향**입니다.
  명세가 요구하는 07~09시 현장 실측을 대신하지 못합니다.
- **등기·소송** — 공식 API 가 없습니다. 인터넷등기소는 등기부등본 열람 API 를 제공하지
  않고(등기정보광장은 통계만), 소송은 사건번호 없이 주소로 역검색할 방법이 없습니다.
  최종 후보 2~3곳으로 좁힌 뒤 **사람이 열람**하는 것이 유일한 길입니다.
- **기존점 실매출** — 외부에 없습니다. 타브랜드는 공정위 공시로 **대조선**까지만
  만들 수 있습니다(`collect_benchmarks.py`, 연 1회 갱신).

## 간편 입력 (`quick_site.py`) — 주소와 마진율만

후보지 CSV 는 26개 열을 요구하지만, 사람이 반드시 알아야 하는 것은 둘뿐입니다 —
**어디인가**와 **얼마를 남기는가**. 나머지는 받아오거나 가정할 수 있습니다.

```bash
# 주소로 (KAKAO_REST_KEY 필요)
KAKAO_REST_KEY=... python3 quick_site.py --주소 "서울 성동구 연무장길 42" --마진율 55

# 좌표로 (키 없이 — 입력 페이지에서 주소를 검색하면 좌표가 나옵니다)
python3 quick_site.py --위도 37.5445 --경도 127.0557 --법정동코드 1120010300 \
                     --이름 "성수 연무장길" --마진율 0.55

python3 review_sites.py --sites output/quick/sites.csv --settings output/quick/설정.yaml
```

마진율은 **공헌이익률**입니다(변동비율 v = 1 − 마진율). 로열티·광고분담금은 계약으로
정해진 값이라 설정값을 그대로 두고 나머지를 원재료율로 돌립니다.

> ⚠ 이 저장소에서 `margin` 은 `(매출−BEP)÷매출` 로 **결과**를 가리킵니다. 여기서 받는
> 마진율은 **입력**인 공헌이익률이라 이름이 겹칩니다. 산출물에서는 '공헌이익률' 로 적습니다.

### 칸마다 어디서 온 값인지 남깁니다

`output/quick/출처표.md` 가 26칸을 다섯 분류로 나눠 보여 줍니다.

| 분류 | 뜻 |
|---|---|
| 자동수집 | 외부 API 에서 실제로 받아온 값 (좌표·법정동코드·지역 시세) |
| 역산 | 받아온 값에서 계산한 값 (지역 시세 → 추정 임대료) |
| 가정 | **근거 없는 자리표시자 — 실사로 대체해야 합니다** |
| 미확인 | 빈칸으로 둔 치명 항목 |
| 미확보 | 채우지 못한 값 |

가정값은 **모르는 조건을 불리한 쪽으로** 잡습니다. 코너·주차·정차·방향적합을 `Y` 로
두면 Mode B 배점이 근거 없이 올라가고, 그렇게 나온 통과는 실사에서 뒤집힙니다.
치명 플래그 4종은 **채우지 않습니다** — `N` 은 '실사해서 문제없었다' 는 뜻이고,
실사하지 않은 것을 그렇게 적으면 거짓말이 됩니다.

### 이 입력으로 확정할 수 없는 것

채우지 못한 칸이 아니라, **외부에서 받아올 방법이 아예 없는 것들**입니다.

- **유동인구 D_am** — 명세가 07~09시 현장 실측 카운트를 요구합니다. 공개 데이터로
  대체할 수 있는 값이 아니며, M2 수요의 핵심 변수입니다.
- **기존점 실매출** — 회사 내부 자료입니다. 없으면 M4 는 회귀(Mode A)도 앵커링(Mode B)도
  못 하고, 매출 추정이 없으면 margin·BEP 판정이 서지 않습니다.
- **치명 항목 4종** — 등기·임대인·소송·인허가는 실사로만 확인됩니다.

간편 입력으로 만든 후보지가 섞이면 **심의표 머리말에 경고가 붙습니다.**
그 판정은 후보지를 추리는 용도이며 출점 결정의 근거가 되지 않습니다.

## 실거래가 (`collect_transactions.py`)

후보지의 법정동코드로 **국토교통부 상업업무용 부동산 매매 신고 자료**를 받아 지역 시세
요약을 만듭니다. 심의표에 `## 지역 실거래가 (M5 시세 대조 근거)` 절로 실리고,
**M5 판정의 시세 대조 신호**로 들어갑니다.

```bash
python3 collect_transactions.py                              # dry-run — 호출 없음
DATA_GO_KR_KEY=... python3 collect_transactions.py --live --months 12
./run_all.sh --live                                          # 전체 파이프라인에 포함

# 심의표를 뽑으면서 파이프라인이 직접 받아오게 하려면
DATA_GO_KR_KEY=... python3 review_sites.py --실거래-수집 --실거래-개월 12
```

키는 공공데이터포털(data.go.kr)에서 해당 자료를 **활용신청**한 뒤 발급받습니다.
승인까지 시간이 걸리며, 키가 없으면 `--live` 는 실행을 거부합니다. 수집은 **켤 때만**
일어납니다(`--실거래-수집`) — 심의표를 뽑을 때마다 외부 API 를 두드리면 키가 없는
환경에서 파이프라인이 멈추고 쿼터도 모르게 소모됩니다. 평소에는 저장된
`output/실거래가.csv` 를 읽습니다.

### 판정에 어떻게 들어가는가

매매가는 임대 조건이 아니라서 그대로는 비교할 수 없습니다. 그래서 **매매 시세를 기대
임대료로 환산**한 다음 제시 임대료와 대조합니다.

```
건물가치     ≈ 지역 중앙 만원/㎡ × 전용면적_평 × 3.305785
기대 월임대료 ≈ 건물가치 × 상업용_연임대수익률(0.045) ÷ 12
제시 임대료 > 기대 × 시세대비_보류배수(2.0)   →  보류
```

설계상 지켜야 할 선이 셋 있습니다.

- **보류까지만 합니다.** 환산값은 층·용도·전면 편차를 못 담습니다. 근거가 약한 신호로
  후보지를 탈락(부결)시키지 않습니다.
- **데이터가 없으면 완전한 무동작입니다.** 실거래 표본이 `시세대조_최소건수`(5) 미만이거나
  전용면적·법정동코드가 비면 대조 자체를 건너뜁니다. 시세를 못 받은 지역의 후보지가
  그 때문에 불리해지면 안 됩니다.
- **환산 계수는 미검증(ESTIMATED)입니다.** `상업용_연임대수익률`·`시세대비_보류배수`·
  `시세대조_최소건수` 셋 다 심의 콘솔에서 조정할 수 있고, 심의표의 '미검증 계수' 절에
  그대로 실립니다. 산출물의 '비고' 에도 어떤 가정으로 환산했는지 한 줄로 남습니다.

**매출 추정(M1~M4)에는 들어가지 않습니다.** 상업용은 층·용도·전면에 따라 편차가 커서
회귀의 설명변수가 될 수 없습니다. 요약은 평균이 아니라 **중앙값**을 씁니다 — 대형 거래
한 건이 평균을 통째로 끌어올립니다.

dry-run 은 **거래 행을 만들지 않습니다.** 금액을 지어내면 심의표에 그대로 실려 실측으로
오인되기 때문입니다(빈 표만 만듭니다).

> ⚠ **엔드포인트와 응답 필드명이 실제 호출로 검증되지 않았습니다.** 서비스키가 없어
> 한 번도 호출해 보지 못했습니다. 파서는 한글·영문 태그를 함께 받고, 포털이 오류를
> HTTP 200 에 XML 로 담아 보내는 것도 오류로 처리하며, **항목을 하나도 못 읽으면 응답
> 앞부분을 그대로 출력**합니다. 형식이 다르면 그 출력을 보고
> `collect_transactions.py` 의 `ENDPOINT` / `FIELDS` 를 고치면 됩니다
> (`--endpoint` 로 주소만 갈아끼울 수도 있습니다).
