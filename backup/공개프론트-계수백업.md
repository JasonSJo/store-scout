# 공개 프론트엔드에 있던 값 — 제거 전 백업

2026-09-02. 옛 공개 화면(`cafe-trade-area/index.html` · `input/` · `consult/` · `shared/`)을
React 프론트로 교체하면서 지운 값들이다. 태그 `백업/공개프론트-제거전` 에 그 시점 전체가 남아 있다.

## 왜 지웠는가

이 값들은 **GitHub Pages 로 배포되는 자바스크립트 안에** 있었다. 사이트를 여는 누구나
브라우저 개발자도구로 읽을 수 있었다 — 회사의 인건비 구조, 차입 가정, 변동비율,
그리고 판정 공식이다.

## 지운 값과, 그 값의 진짜 자리

프론트에 있던 것은 전부 **사본**이었다. 원본은 백엔드에 있고 파이프라인은 원본을 쓴다.
그러므로 아래 표의 '원본' 열이 살아 있는 한 지운 것으로 잃은 값은 없다.

## 함께 사라진 기능

값만 지운 것이 아니라 그 값을 쓰던 화면도 함께 내렸다. 되살리려면 **사내 콘솔 안**이
맞는 자리다 — 로그인 뒤라야 계수를 화면에 띄울 수 있다.

- **상담 화면의 손익분기 미리보기** — 임대료별 BEP 구간표, 운영형태 3종 비교표
- **데이터 입력 화면 전체** (`input/`) — 후보지 실사 20칸 입력, 주소 검색, 지도, 간편 입력,
  `sites.csv` 내보내기. 파이프라인 입력을 만드는 도구라 공개 자리에 둘 것이 아니었다.

## 남은 문제 — 저장소가 public 이다

프론트에서 지웠어도 `analysis/` 는 이 저장소에 그대로 있고, 저장소는 공개다.
즉 **위 값들은 지금도 github.com 에서 누구나 읽는다.** 프론트 제거만으로는 목적이
이루어지지 않는다. 저장소를 비공개로 돌리거나, 프론트와 백엔드를 서로 다른 저장소로
가르는 결정이 따로 필요하다.

## 옮기면서 남은 계약 불일치 — 아직 안 고쳤다

React 상담 화면이 내려주는 JSON 이 파이프라인이 읽는 키와 다르다. "보내준 react 대로만"
이라는 지시에 따라 화면 동작은 건드리지 않았다. 붙이는 날 이 표대로 맞추면 된다.

| 파이프라인 (`analysis/consult.py:36`) | React (`web/app/consultation/page.tsx`) |
|---|---|
| `고객전화번호` | `전화번호` |
| `보증금_만원` · `권리금_만원` | `보증금만원` · `권리금만원` |
| `희망지역` — 문자열 목록 | `[{city, district}]` |
| `희망상권` — 목록(복수 선택) | 문자열 하나 |

그리고 **파일이 하나다.** 옛 화면은 둘로 갈랐다 — 상담카드(개인정보 포함, 상담사 보관)와
`조건.json`(개인정보 제외, 파이프라인 입력). React 는 고객명·전화번호까지 한 파일에 담아
내려준다. 그 파일을 그대로 파이프라인에 넣으면 개인정보가 백엔드로 들어간다.
`consult.py:228` 이 읽는 키만 골라 다시 쓰긴 하지만, **들어가지 않는 것과 들어갔다가
걸러지는 것은 다르다.**
