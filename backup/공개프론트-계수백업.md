# 공개 프론트엔드에 있던 값 — 제거 전 백업

2026-09-02. 옛 공개 화면(`cafe-trade-area/index.html` · `input/` · `consult/` · `shared/`)을
React 프론트로 교체하면서 지운 값들이다. 태그 `백업/공개프론트-제거전` 에 그 시점 전체가 남아 있다.

## 왜 지웠는가

이 값들은 **GitHub Pages 로 배포되는 자바스크립트 안에** 있었다. 사이트를 여는 누구나
브라우저 개발자도구로 읽을 수 있었다 — 회사의 인건비 구조, 차입 가정, 변동비율,
그리고 판정 공식이다.

## 지운 값과, 그 값의 진짜 자리

프론트에 있던 것은 전부 **사본**이었다. 원본은 백엔드에 있고 파이프라인은 원본을 쓴다.
그러므로 아래 표의 '원본' 열이 살아 있는 한 지운 것으로 잃은 값은 없다.

| 값 | 지운 자리 | 원본 (백엔드) |
|---|---|---|
| 운영형태 고정인건비 — 오토 980 · 점주+알바 620 · 점주 260 (만원/월) | `consult/js/fields.js` | `analysis/설정.example.yaml` → `운영형태` |
| 투자금형태 — 대출비율 0.5 · 연금리 0.06 · 리스 45만원/월 | `consult/js/fields.js` | `analysis/설정.example.yaml` → `투자금형태` |

| 기타 고정비 170만원/월 | `consult/js/calc.js` · `input/js/quick.js` | `analysis/설정.example.yaml` → `기타_월_만원` |

`설정.example.yaml` 을 견주고 있었고, 지금도 백엔드 안에서 같은 대조를 한다.

## 함께 사라진 기능

값만 지운 것이 아니라 그 값을 쓰던 화면도 함께 내렸다. 되살리려면 **사내 콘솔 안**이
맞는 자리다 — 로그인 뒤라야 계수를 화면에 띄울 수 있다.

- **상담 화면의 손익분기 미리보기** — 임대료별 BEP 구간표, 운영형태 3종 비교표
- **데이터 입력 화면 전체** (`input/`) — 후보지 실사 20칸 입력, 주소 검색, 지도, 간편 입력,
  `sites.csv` 내보내기. 파이프라인 입력을 만드는 도구라 공개 자리에 둘 것이 아니었다.

## 남은 문제 — 저장소가 public 이다

프론트에서 지웠어도 `analysis/` 는 이 저장소에 그대로 있고, 저장소는 공개다.
즉 **위 값들은 지금도 github.com 에서 누구나 읽는다.** 프론트 제거만으로는 목적이
이루어지지 않는다. 저장소를 비공개로 돌리거나, 프론트와 백엔드를 서로 다른 저장소로
가르는 결정이 따로 필요하다.

## 옮기면서 남은 계약 불일치 — 화면 쪽은 고쳤다

React 상담 화면이 내려주던 파일은 하나였고, 그 키가 파이프라인이 읽는 키와 달랐다.
2026-09-03 에 화면 쪽을 고쳤다 — **파일을 둘로 가르고, 형식을 CSV 로 바꾸고,
키 이름을 `analysis/consult.py` 의 `읽는키` 에 맞췄다.**

| 내려받는 파일 | 개인정보 | 담기는 것 | 쓰는 자리 |
|---|---|---|---|
| `상담카드_{고객명}_{시각}.csv` | **있다** — 고객명·전화번호·거주지·근무지 | 개인정보 + 조건 전부 | 상담사가 보관 |
| `조건_{시각}.csv` | 없다 | `읽는키` 7칸만 | 파이프라인 입력 |

`조건` 파일 이름에는 고객명을 넣지 않는다 — 파일 이름도 개인정보다.

두 파일이 계속 어긋나지 않도록 테스트로 묶어 두었다
(`tests/test_saas.py` · `TestFrontendBackendSplit`):

- `test_조건파일이_파이프라인_키를_그대로_쓴다` — `consult.py` 의 `읽는키` 를 직접 읽어
  화면의 CSV 머리글과 글자 그대로 대조한다. 어느 쪽 이름을 바꿔도 걸린다.
- `test_조건파일에_개인정보_키가_없다`
- `test_조건파일_이름에_고객명이_없다`

이름이 어긋나도 **아무 데서도 터지지 않는다** — `consult.py` 는 `cond.get(키)` 로 읽으므로
어긋난 칸은 빈 값이 되고, 필터가 아무것도 거르지 않은 채 후보지가 전부 심의에 올라온다.
조용히 틀리는 고장이라 사람 눈으로 지킬 수 없다. 그래서 테스트로 막았다.

### 파이프라인도 CSV 를 읽는다 (2026-09-03)

`consult.py` 의 `load_consult()` 가 JSON 과 CSV 둘 다 받는다. 형식은 확장자가 아니라
내용으로 가린다(`{` 로 시작하면 JSON). CSV 는 두 모양이 온다.

- **`조건.csv`** — 머리글 한 줄 + 값 한 줄. 목록 칸(`희망지역`·`희망상권`)은 `·` 로
  다시 가른다. 화면이 라디오라 `희망상권` 이 하나만 오는데, 원소 하나짜리 목록이 된다.
- **`상담카드.csv`** — `항목,값` 세로 표. 잘못 넣는 실수는 나므로 읽기는 하되,
  `main()` 이 "개인정보 N건" 경고를 내고 산출물에는 싣지 않는다 — 종전 JSON 때와 같다.
  `희망지역_1순위`·`_2순위` 는 `희망지역` 목록으로 모은다.

브라우저가 실제로 내린 `조건.csv` 로 끝까지 돌려 확인했다. 그러다 **지역 필터의
버그를 하나 찾았다** — 화면은 시·도를 정식 명칭(`서울특별시 강남구`)으로 보내고,
후보지 주소는 사람이 줄여 적는다(`서울 강남구 강남대로 396`). 필터가 통째 문자열
포함으로 보고 있어서 **후보지 6곳이 6곳 다 "희망 지역에 해당하지 않음"으로 빠졌다.**
낱말마다 보도록 고쳤고(`지역맞음()`), 시·도 낱말은 통용 표기(`서울`·`경기`·`충북`…)도
인정한다. 옛 JSON 식 한 낱말(`강남`)도 그대로 된다.

`매매총예산_만원` 과 `월세상한_만원` 은 v7 화면에서 따라온 칸으로 파이프라인에 짝이 없다.
`조건` 파일에는 넣지 않았고 `상담카드` 에만 남겼다.
